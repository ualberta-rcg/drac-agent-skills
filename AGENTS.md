# Working on drac-agent-skills

- **Single source of truth for skills**: Core Alliance cluster skills live once in `skills/<name>/SKILL.md` (`etc/claude-code/.claude/skills -> ../../../skills`, `etc/agents/skills -> ../claude-code/.claude/skills`, `etc/codex/skills -> ../agents/skills`). Curated domain research skills live once in `community-skills/skills/<name>/SKILL.md`. Both match [`gh skill install`](https://cli.github.com/manual/gh_skill_install)'s non-hidden `skills/` discovery convention — never duplicate `SKILL.md` files across directories.
- **Keep `etc/claude-code/CLAUDE.md` and `etc/agents/AGENTS.md` aligned**: Both files provide the shared cluster operating instructions across harnesses; update them together whenever core cluster guidance changes.
- **Preserve the open login-node baseline**: `etc/claude-code/managed-settings.json` mirrors the user-accepted live login-node policy (normal `ssh`, `scp`, `sudo`, and workspace operations remain unobstructed, while destructive commands and credential reads are blocked). Keep `etc/pi/extensions/hpc-guardrails.ts`, `etc/codex/{config,requirements}.toml`, `etc/opencode/opencode.json`, `etc/gemini-cli/`, and `cursor/cli-config.json` equally open. Put optional tighter controls (such as remote-control daemon blocks or extra telemetry flags) **commented out** in configs that support comments, or documented as opt-in snippets in `README.md` for strict JSON files.
- **Secrets, PII, and scope hygiene**: Backend templates (`claude/`, `pi/`, `opencode/`, `aider/`) must use `"Put-Key-Here"` placeholders only. Never commit real API keys, tokens, user PII, internal private network addresses, host-hardening playbooks, or API gateway provisioning scripts.
- **Validation before finishing**: Check JSON syntax with `jq empty`, shell scripts with `bash -n`, OpenCode configs with `opencode debug config` when available, and `SKILL.md` frontmatter (`name` matching folder name + non-empty string `description`). Record notable changes in `CHANGELOG.md`.
- **Live cluster boundary**: This repository stages files for Warewulf login-node overlays and standalone installs; permission to edit repository files is not permission to overwrite live `/etc` files or restart system services on a shared cluster.
